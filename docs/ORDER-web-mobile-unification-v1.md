## 적용 목적과 개발 기준

**대표 지시 · 2026-11-24 · 적용 대상: 모두웹과 모바일 앱 개발 담당자.** 앞으로 제품 방향·브랜드·공통 동작·데이터 의미는 모두웹에서 확정한 기준에 맞춘다. 모바일은 손가락 조작과 작은 화면에 맞게 구현하되, 같은 계정과 같은 매물을 두 제품처럼 다르게 해석하지 않는다.

기존 모바일 기능과 자료를 보존하면서 화면·흐름 단위로 정렬한다. 웹의 미완성 기능이나 오류를 모바일에 복제하지 않는다. 이번 오더 작성은 모바일 구현·공유 DB 변경·운영 배포 실행과 구분한다.

로고를 다시 그리거나 임의 색으로 바꾸지 않는다. 작은 모바일 인라인 스피너의 기존 적합한 동작은 보존하며 PC 로딩 GIF로 일괄 교체하지 않는다. PC의 1280px 뷰포트·사이드바·넓은 표를 모바일 앱에 복사하지 않는다. 휴대폰에서 PC 주소를 표시하는 정책과 별도 모바일 앱은 구분한다.

양도인·소유주·창업자·사장님·기업회원·방문자의 역할 ID와 표시를 유지한다. 양도인은 매물·권리금·동향, 소유주는 상가·매매가·임대료·시세의 어휘를 쓴다. 미확정 카피·평점·성사 보장·가짜 숫자를 추가하지 않는다. 미구현은 예정 상태로 표시하고, 조회 실패·권한 제한·정상 0건을 구분한다.

일반 사진 영역은 PC의 `PhotoImage`와 `photo-unavailable.svg` 기준으로 사진 0장·깨진 URL을 일관되게 처리한다. 앱의 quiet 비공개 업종 아이콘은 정보 보호 표현이므로 ‘사진 없음’과 구분해 유지한다.

**향후 상품 방향도 공통으로 보존한다.** 직접 거래하는 프리미엄 매물의 우선 공간과 직원의 고객 DB를 통한 적합 고객 추천·알림 시스템을 기획 시 반영한다. 11월 18일에 저장한 아이디어이며, 이번 통일화로 추천 발송·상품 과금·고객 DB 기능을 즉시 구현하거나 실제 구축을 주장하지 않는다. 일반 시장의 자연 검색 순위와 별도 상품 공간을 구분한다.

새 필드·enum·상태·공개 범위·권한을 한쪽에서 임의 변경하지 않는다. 공유 DB·Storage·RLS·grants·publication 변경은 UI 통일과 분리하고 기존 단일 작성·대표 실행 절차를 따른다. 기존 계정 소유권을 재배정하거나 이미 완료한 949건·610건 적재, 계정 1,000개 생성과 로고 연결을 재실행하지 않는다. 유통은 제품 설계에서 빠뜨리지 않되 새 DB 업체 분류를 임의로 추가하지 않는다.

## 적용 순서

1. **현황 고정:** 양쪽 커밋·변경 파일, 화면/기능별 일치·불일치·미완료 표를 작성한다. 이미 일치한 색·로고·토큰과 완료된 공유 필드 구현은 변경 대상에서 제외한다.
2. **기준과 보호 대상 등록:** 모바일 담당자는 이 오더를 작업 시작 지침에서 참조하고 옛 ‘앱 원본’ 규칙과의 우선순위를 정리한다. 현재 사용자 작업과 미커밋 파일을 보존한다.
3. **P0부터 적용:** 같은 매물 ID의 핵심 정보와 오류 상태를 먼저 맞춘 뒤 사진·탐색·공개 디렉터리를 작은 검증 가능한 묶음으로 진행한다.
4. **화면별 왕복:** 목록 → 상세 → 수정 → 목록 복귀에서 같은 데이터와 공개 범위가 유지되는지 확인한다. 모바일 역할 전환·뒤로가기·OAuth 복귀·초안·미저장 경고를 보존한다.
5. **후속 계약 반영:** PC에서 새 공통 규칙이 확정될 때마다 변경 목록과 수용 조건을 전달한다. 전면 재작성이나 일괄 화면 교체로 확장하지 않는다.

앱에서 완성된 매출·메시지·온보딩·권한·quiet 동작은 PC의 미완성 수준에 맞춰 삭제하거나 간소화하지 않는다. PC 기업회원 ‘내 업체 관리’ 등 미완성 항목은 별도 상태로 기록한다. E1 관련 변경은 기존 양도인 스냅샷과 보호 규칙을 적용한다.

## 변경 전달과 완료 검증

## 앞으로 매번 지킬 전달 규칙

PC에서 공통 변경을 확정하면 PC 담당자가 변경 ID·기준 커밋·관련 파일·기존/변경 동작·저장 필드·모바일 적용점·수용 검사를 기록한다. 모바일 담당자는 이를 모바일 구조로 반영하고 자신의 변경 커밋·스크린샷·검증 결과를 같은 변경 ID로 회신한다. 토큰 이름/값과 필드 계약의 의미는 임의로 갈라지지 않게 한다.

기록 상태는 **기준 확정 → 모바일 전달 → 모바일 반영 → 양쪽 검증**으로 구분한다. 문서 작성만으로 전달·수신·반영·배포 완료를 표시하지 않는다. 중요한 제품 의미·공개 범위·DB 변경은 대표 판단을 받고, 이미 확정한 토큰·명칭·표시 규칙의 동기화를 이유로 같은 승인을 반복 요청하지 않는다. 기기별 배치만 다른 수정까지 양쪽 동시 배포 의무로 만들지 않는다.

## 화면 묶음별 수용 검사

- 같은 계정과 같은 매물 UUID로 제목·거래유형·가격 단위·공개 상태·소개 수정문·사진 순서를 PC/모바일에서 비교한다.
- lease/sale/both, 공개/협의중/숨김/초안/판매완료/삭제, 상호·위치 비공개와 quiet 조합을 확인한다. UI 명칭과 원장 상태를 혼동하지 않는다.
- 사진 0장·깨진 URL·내부 또는 도면만·외관만·삭제 후 재편집, 조회 실패·권한 제한·정상 0건을 각각 검사한다.
