# ORDER-e1p-shell-eliminate-v2 — "실제 앱에서..." 전면 검수 + 빈껍데기 실구현 (v1 대체)

## 모드: 자율 판정. 멈춤 (a)(b)(c)만.

## 원칙
"실제 앱에서 할 수 있어요" 류 전면 금지 — 이것이 실제 앱. 지금 구현 가능(기존 인프라 재사용 포함)은 전부 실구현. 인프라 부재만 (예정) 유지.

## 1부: 프로토타입 잔재 전면 검수 (전 축·전 화면)
grep: "실제 앱/실제 서비스/실서비스/정식 버전/정식 출시/출시 후/출시되면/앱에서는/데모/프로토타입/여기서는/지원 예정입니다" + 유사 확장. 토스트·플레이스홀더·빈상태·비활성 안내 포함.
판정표: 문구/파일:줄/판정([즉시 구현—인프라 존재]|[(예정) 유지—인프라 부재])/처리.
즉시 구현은 이 오더 안에서 전부. (예정)은 planned-label 규격(완료 위장 금지·틀 보존).
재발 방지: 잔재 문구 부재 회귀 테스트.

## 2부: 확정 실구현 3건
a. E1p 사진 업로드 — E1 실업로드 재사용(도면·외관 슬롯 유지, image_urls 실저장, 복제 금지). 가이드 "사진" 단계 복원 판정 보고.
b. E1p 위치·상권 분석 — E1 marketData 재사용, Step2 해당 (예정) 해제. 상가 맥락 지표만. 등기·건축물·시세는 (예정) 유지.
c. E2L 소유자 액션 — 내리기(hidden)·삭제. 양도인 상태 전환 패턴 재사용, 삭제 확인 다이얼로그. FK 미확정 → 소프트 삭제(hidden 영구+목록 제외), 하드는 FK 확정 시.

## 테스트: 잔재 부재 회귀 + 사진→E2L / 상권 렌더 / 내리기 노출 규칙 / 삭제 플로우. 전체.
## 보고: 4줄(ls-remote) + 판정표 전문 + 가이드 사진 복원 판정 + 삭제 정책 근거.
