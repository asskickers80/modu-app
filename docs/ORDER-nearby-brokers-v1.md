# [ORDER-nearby-brokers-v1-final] 내 주변 부동산 카드 — 기업회원 유료 노출의 원형 (통합본)

■ 모드: 자율 판정. 멈춤 (a)스키마 SQL (b)실DB 정정 (c)판정 불가만.

## 비전 (대표 확정)
홈의 "내 주변 부동산" 3자리는 최종적으로 기업회원(부동산·컨설팅) 유료 노출 자리다.
외부 데이터는 기업회원이 채워질 때까지의 임시 채움이며, 입점사가 늘수록 자동 대체된다.
원칙: 외부 업소는 "여기 있다"까지만 — 표현·유입·연결은 입점사의 것.

## 1. 표시 위치·톤
- 양도인·임대인 홈 공통, "+ 새 등록" 링크 아래 "내 주변 부동산" 카드.
- 등록 동선을 가로막지 않는 곁 정보. "의뢰하세요" 류 권유 문구 금지.
- 기준 위치: 등록 상가/매물 주소 (복수면 완성도 대표 상가와 통일 판정 자율)
  → 0건이면 A3 지역 답변 폴백 → 그것도 없으면 카드 미표시 (가짜 지역 금지).

## 2. 슬롯 로직 (3단계 생애주기 내장)
- 1단계(현재): 입점 0곳 → 3자리 전부 외부 참고.
- 2단계: 입점 N곳 → 입점사 무조건 상단 우선, 빈 슬롯만 외부 채움.
- 3단계: 입점 3곳 이상 → 외부 표시 완전 종료, 전원 기업회원.
- 기업회원 테이블·카테고리 구조 확인: 활동지역 매칭 필드 부재 시 슬롯 로직 구조만
  구현하고 입점 조회는 (예정) 주석, 필요 스키마 SQL 제시 후 멈춤(a).

## 3. 표시 격차 (외부 vs 입점)
[외부 참고]: 상호 · 동 단위 주소 · 거리. 끝.
  - 탭 = 네이버 지도/플레이스 외부 링크 (앱 내 상세 없음).
  - 전화·사진·설명 등 표현 요소 일절 없음. "참고 정보" 라벨 명시 (제휴 위장 금지).
[모두 입점]: 상호 + 입점 뱃지 + 대표 사진/로고 + 한 줄 홍보 문구(입점사 작성) +
  전문 분야 태그.
  - 탭 = 앱 내 상세 (소개·연락·향후 상담 연결 동선).
  - 홍보 문구는 입점사 입력값 — 우리가 생성·과장하지 않음. 표현 규율(수익 보장 금지 등)은
    기업회원 축 설계 때 등록 확인사항으로, 이번엔 필드 구조만.

## 4. 데이터 소스 (외부 채움용)
- 네이버 지역 검색 API — 기존 개발자센터 계정에 "검색" API 활용신청 (대표 실행,
  절차를 보고에 안내할 것).
- 좌표 기반 "부동산중개" 검색, 서버 프록시 경유 (기존 프록시 패턴 재사용),
  일 1회 캐시 (홈 진입마다 호출 금지 — 비용 원칙).
- 키 도착 전: 카드 자체를 렌더하지 않음 (준비중 껍데기 금지, 키 도착 시 활성).

## 테스트
슬롯 우선순위 (입점/외부 혼합·입점 3곳 초과 시 외부 배제), 위치 폴백 체인
(상가→A3→미표시), 외부 탭 = 외부 링크·입점 탭 = 앱 내 상세 분기, 캐시 동작.
전체 스위트.
