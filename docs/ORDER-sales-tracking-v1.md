# [ORDER-sales-tracking-v1] 사장님 매출 관리 — 입력·분석·비교 (1~3단계 통합)

■ 모드: 자율 판정. 멈춤 (a)스키마 SQL (b)실DB 정정 (c)판정 불가만.
■ 장치 3(양도인 diff 요약) 의무 — 양도인 경로 무영향 증명.

## 목표 (대표 확정)
사장님(운영중) 축이 캐시노트 수준의 효용을 내도록 매출 입력·분석·비교를 구현한다.
입력 소스는 수기(30초 원칙), 분석·리포트 층은 자동 수집 서비스와 동등 수준을 지향.
POS·카드 연동은 (예정) — 이번 범위 아님. 양도 증빙 연결은 구조만 남기고 기능은 후속.

## 1. 홈 배치 (선행)
사장님 홈 최상단 = 매출 카드. 그다음 "오늘 할 일"(후속 오더) 자리 확보.
기존 "오늘의 한 마디"·지표·콘텐츠 블록은 그 아래로. 양축(양도인·임대인) 무영향.

## 2. 입력 (30초 원칙)
- 홈 카드에서 바로 입력 (별도 화면 진입 없이, 필요 시 시트).
- 필수: 오늘 매출 (숫자). 키패드 + 만원 단위 빠른 칩(+10만/+50만 등) 병행.
- 선택: 손님 수 / 메모(1줄).
- 배달 매출 (조건부, 선택): 업종이 요식업 계열이고 "배달 함" 설정 시에만 노출.
  배달 여부는 온보딩 또는 매출 설정에서 1회 확인.
- 소급 입력 7일까지. 어제 미입력 시 "어제도 넣을까요?" 유도.
- 저장 즉시 카드에 반영 (오늘 매출 표시).

## 3. 고정비 설정 (월 1회)
- 임대료·인건비·관리비·기타 — 월 단위 설정, 변경 시에만 수정.
- 매출 카드 또는 설정 진입점에서 관리. 미설정이어도 매출 기능은 정상 동작.
- 후속 "오늘 할 일"(일정관리)의 재료 — 구조를 그에 맞게 (납부일 필드 판정 자율, 근거 보고).

## 4. 분석 (입력량에 따라 열리는 구조 — 없는 건 침묵)
- 3일+: 요일 패턴 시작 / 1주+: 지난주 대비·요일별 비교 / 2주+: 객단가 추이·홀/배달 비중
  / 1달+: 월 추이·고정비 대비 여유·다음 달 예상.
- 데이터 충분할 때만 표시, 부족하면 "○일 더 기록하면 ○○을 볼 수 있어요" 안내
  (가짜 수치·추정 표시 금지 — 정직 원칙).
- 계산은 룰/SQL. Gemini는 해석 문구에만 (비용 원칙).

## 5. 동네 대비
- 초기: 소진공 상권 API 실값 기반 밀집도 표현만 (반경 내 동종 업소 수 등).
  매출 비교는 하지 않음 — 표본 승격 전까지 매출 비교 문구·수치 일절 금지.
- 표본이 쌓이면 매출 대비로 자연 승격 가능하도록 구조 설계 (기준 판정 자율, 근거 보고).

## 6. 데이터 구조 (양도 연결 대비)
- 매출 기록 = 일 단위 행 (날짜·매출·손님수·배달매출·메모). 기간 집계로 양도 증빙 생성
  가능한 형태 유지 — 이번엔 구조만. roleData.operating과 연결.
- 스키마 SQL 제시 후 멈춤(a). 매출·고정비 테이블 설계 포함.
- SQL 미실행 상태에서도 기존 기능이 깨지지 않도록 (title 사고 재발 방지 규칙).

## 7. 연동 (예정) 처리
- "POS·카드매출 연동" 버튼: (예정) 규격. 탭 시 "어떤 POS를 쓰시나요?" 수집 →
  "연동이 준비되면 알려드릴게요" (수집값 저장 — 제휴 우선순위 자산).
- 없는 기능을 있는 것처럼 표시 금지.

## 테스트
입력 저장·소급·배달 조건부 노출 / 단계별 분석 열림·부족 시 안내 / 고정비 반영 /
동네 밀집도 표시 / (예정) 버튼. 전체 스위트.
