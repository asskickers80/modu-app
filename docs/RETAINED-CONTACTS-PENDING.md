# 탈퇴자 연락처 보관 — 법률 검토 대기

> ORDER-key-proxy-account-deletion B-5 · 2026-09-06

## 상태
**만들지 않았다.** `retained_contacts` 테이블도, 이관 배치도 없다. 법률 검토 전이다.

## 이번에 만든 것 (여기까지만)
- `consents` 테이블에 `retention_after_withdrawal` 동의 유형을 **정의만** 해 두었다.
- 회원가입·온보딩에서 이 동의를 **받는 자리**까지만 만든다. 미체크가 기본이고,
  체크하지 않아도 가입이 끝까지 진행된다.

## 검토가 끝나기 전까지 지켜야 할 것
- 탈퇴 시 개인식별정보는 **실제로 파기**한다. 다른 테이블로 옮기지 않는다.
  옮기면 그것은 백업이지 파기가 아니다.
- 동의를 받아 두었더라도, 보관 이관 로직이 없으므로 현재 탈퇴자 연락처는 남지 않는다.
  이것이 의도된 상태다.

## 검토가 필요한 지점
1. 개인정보보호법상 파기 의무와 "별도 동의를 받은 보관"의 경계
2. 보관 기간 상한과 자동 파기 시점
3. 보관 목적(재가입 안내·중개 서비스)의 적법성 범위
4. 동의 철회 시 즉시 파기 절차
