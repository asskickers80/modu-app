# [ORDER-draft-quality-v1] 소개글 품질 종합 — 분량·블록 확장·시설 연차·유료 블록·표기 버그

■ 모드: 자율 판정. 멈춤 (a)스키마 SQL (b)실DB 정정 (c)판정 불가만.
■ 적용: 양도인(E1)·임대인(E1p) 공통. 장치 3(양도인 영향 diff 요약) 의무.

## 1. 블록 구성 확장
- 프랜차이즈 (조건부): 매물이 프랜차이즈일 때만 생성·표시. 공정위 franchise 데이터
  (11,683건 매핑 기존 인프라) 연결 — 브랜드 확인되면 가맹 현황 등 확인 사실 기반 서술.
  독립 점포는 블록 자체 없음. 임대인 상가는 해당 없음 판정 (권장 업종 블록이 그 역할) —
  다르게 판단되면 근거 보고.
- 특이사항/경쟁력 (유료 전용): 4번 참조.
- 순서: 프랜차이즈는 시설 뒤, 특이사항/경쟁력은 최후미 배치 판정 자율.

## 2. 블록당 분량 강제 (+ 날조 방지 동시)
프롬프트에 블록당 최소 3~4문장(앱 화면 3줄+) 지시. 반드시 병기: "확인된 사실과 정성
서술로 채우되, 사실이 부족하면 짧아도 된다. 분량을 위해 수치·시설·지명을 만들어내지
않는다." 실출력 샘플로 블록별 분량 검증 (양도인·임대인 각 1건).

## 3. 시설 연차 입력
- 규격: 1년 미만=개월 직접 입력(1~11) / 1~5년=연 선택 / "5년 이상".
- 위치: 시설·집기 입력 단계. 칩/선택 우선.
- 저장 컬럼 필요 → 스키마 SQL 제시 후 멈춤(a). 수정 역매핑 + 왕복 보존 테스트 필수.
- 프롬프트 주입 → 시설 블록 자연 반영. 완성도 배점 편입은 범위 밖(대표 결정 보류).

## 4. 특이사항·경쟁력 블록 — 유료 전용 구조
- 원칙: "유료 = 더 깊은 AI 생성" (직접 순위 판매 금지와 부합).
- 멤버십 미출시: (a) 생성·표시 로직 완전 구현(내부 플래그 검증 가능) (b) 노출은 잠금
  카드 — "멤버십에서 제공될 예정(준비 중)" 톤, 가격·혜택 약속 금지 (c) 플래그 전환만으로
  활성되는 구조.
- 내용: 특이사항=입력값 중 통상 범위 밖 사실 / 경쟁력=상권 실값 대비 강점. 날조 금지.

## 5. 수정 화면 AI 문구 ↔ 실광고 미표기 조사 (조사 후 수정)
원인 특정: (가) item_visibility 기본 비공개 저장 버그 (나) E2/E2L 특정 블록 키 미렌더
(다) 확정 전 미표시 의도 동작. (다)면 UX 충돌 해법 제안, (가)(나)면 수정.
재현: 대표 실기기 케이스 매물 실DB 확인 (읽기).

## 테스트
블록 조건부 생성(프랜차이즈 유/무), 분량 검증, 연차 왕복 보존, 잠금 카드 렌더·플래그
전환, 표기 버그 수정 검증. 전체 스위트.
