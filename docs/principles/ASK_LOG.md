# 질문 로그 저장·분석 규칙 (ASK_LOG)

대표 결정 2026-09-13. '모두에 질문하기'가 남기는 기록을 어떻게 보관하고 무엇에 쓰는지의 단일 기준.
이 문서와 어긋나는 요청을 받으면 구현하지 말고 멈춰서 대표에게 확인한다.

## 1. 두 갈래로 나눠 담는다 (C0·C1)

| | 무엇 | 보관 | 쓰임 |
|---|---|---|---|
| `ask_question_events` | 질문 원문 + 축·의도·분기 | **90일** (이후 원문·식별자만 NULL, 행은 남음) | 새 주제 발견 |
| `ask_question_facts` | 월·축·의도·분기 × 업종·지역·층·면적·연식 구간 × 전환 여부 | **영구** (원문·식별자 없음) | 추세·전환율 분석 |

원문을 지우기 전에 구조화해서 집계에 굳혀 둔다. 그래서 90일이 지나도 "어느 업종·지역에서 어떤 축의 질문이 많고, 그중 몇 %가 문의로 이어졌는가"는 계속 분석할 수 있다. 원문이 꼭 필요한 유일한 용도는 새 주제 발견이고, 그건 90일이면 충분하다.

## 2. 신원 (C1)

- `user_id`를 **직접 저장하지 않는다.** `pseudonym_id` = user_id의 90일 회전 해시이며, 솔트는 서버 환경변수(`ASK_PSEUDONYM_SALT`)에만 둔다.
- 해시는 **서버(`api/ask-log.js`)에서만** 만든다. 브라우저는 솔트를 볼 수 없다.
- 솔트를 회전하면 이전 해시와 연결되지 않는다. 회전 시 이전 솔트는 폐기한다.
- 90일이 지나면 `pseudonym_id`도 NULL로 지운다.

## 3. 저장하지 않는 것 (금지)

- **임베딩·벡터 저장 금지.** 질문을 벡터로 만들어 쌓아 두지 않는다.
- **대화 전문 저장 금지.** DM 내용은 이 로그의 대상이 아니다.
- 연락처·이름·정확한 주소 등 식별 정보.
- 모델 학습용 데이터셋 구축. 모델은 우리 데이터로 학습하지 않는다.

## 4. 양도인 답장 (C4-b·C4-c)

- 답장 원문(`inquiry_ledger.ask_owner_reply_text`)은 **내부 분석 전용 90일**. 같은 파기 배치가 지운다.
- 코드로 금지한다: ① 다른 사용자 질문의 답변 재료로 쓰지 않는다(A4 화이트리스트에 없다) ② 소개글·예시 문구 생성 입력에 넣지 않는다 ③ 기업회원·외부에 노출하지 않는다. 검사 테스트가 이를 고정한다.
- 질문자에게 전달할 때도 **원문 그대로**다. 요약·말투 보정·편집을 하지 않는다.
- 답장을 매물 필드로 옮기지 않는다. "매물에도 적어둘까요?" 류 확인·권유 UI를 만들지 않는다. 매물 정보는 양도인이 직접 등록·수정한 것만이다.

## 5. 분석에 쓰는 것 (C3)

1. 상위 질문 주제 × 업종 × 지역 — 템플릿 풀(`config/listingAsk.ts`) 갱신 근거.
2. ② 비율 상위 축 — 우리가 못 답하는 것 순위. **분기 1회 등록 폼 기본 항목 승격 안건의 유일한 근거**다(개별 매물 즉시 승격은 하지 않는다).
3. 질문→문의 전환율 추이 — 축별·업종별, 질문한 사용자와 안 한 사용자 비교(pseudonym 기준, 90일 내).

쿼리는 `docs/SQL-ask-analysis.sql`. 남의 플랫폼 수치는 화면·문서 어디에도 쓰지 않는다.

## 6. 분류 체계를 굳히지 않는 장치 (C2)

월 1회 `other`(미분류) 상위 50개를 운영 화면(`/dev/ask-topics`)에 띄우고, 사람이 보고 새 `topic_axis`나 새 템플릿으로 승격한다. 이 절차가 있어야 분류가 현실을 따라간다.

## 7. 모델 등급 (A7)

- 무료 등급 모델에는 **사용자 자유 입력·연락처·양도인 답장을 보내지 않는다.** 무료 등급에서 허용되는 유일한 생성 호출은 매물 공개 정보만 쓰는 예시 문구 생성이다.
- 프로덕션에서 자유 입력 생성 경로를 켜려면 `config/ai.ts`의 `ASK.tier`를 `paid`로 바꾼다. 그 전까지 자유 입력은 키워드 룰로만 라우팅한다(기능은 그대로 동작한다).
