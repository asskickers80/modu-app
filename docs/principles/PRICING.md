# 모두 요금제 설계 원칙 (Claude Code 상시 참조용)

이 문서는 원칙과 고려사항이다. 금액·건수 같은 숫자는 대표가 확정하기 전까지 placeholder이며, 전부 `config/plans.ts` 한 곳에 모아둔다. 작성일 2026-09-07. 원본 관리는 채팅(설계) 쪽 프로젝트 문서 `원칙/요금제_설계원칙_PRICING_2026-09-07.md`이며, 이 파일은 그 사본이다.

## 0. 구조 (확정)

세 층이다. 무료 / 프리미엄(개인) / 기업회원 입점.

- **무료**: 방문자·창업준비·양도인·소유주·사장님 모두 기본 기능은 무료. 매물 등록·탐색·DM·매출 입력은 돈을 받지 않는다.
- **프리미엄(개인)**: 양도인·소유주·사장님·창업준비가 구독. 무엇이 들어가는지는 §3.
- **기업회원 입점**: 부동산·인테리어·세무·프랜차이즈·금융 등 서비스 업체. 무료 입점과 유료 입점이 있다. 무엇이 들어가는지는 §2.

랭킹은 팔지 않는다. 이건 요금제 이전의 원칙이다(§1).

## 1. 돈으로 살 수 없는 것 — 코드에 박아두는 규칙

1. **정렬·노출 순서는 결제 등급과 무관하다.** 매물 목록, 기업회원 목록, 수요 신호 응답 카드 정렬 어디에서도 `plan_tier`·결제 여부를 정렬 키로 쓰지 않는다. 정렬 함수에는 주석으로 명시한다: `// 정렬은 결제 등급과 무관 — docs/principles/PRICING.md §1`. 수요 신호 응답 카드는 먼저 답한 순(지시문 E) — 유료 업체가 늦게 답하면 아래.
2. **가짜 희소성·조급함 장치 금지.** "지금 3명이 보고 있어요", "곧 마감", 실제로 없는 할인 타이머 같은 것은 만들지 않는다. 표시하는 숫자는 전부 실제 값이고, 표본이 적으면 숨긴다(정직 원칙).
3. **배지는 사실만.** "충실한 매물", "평균 답장 2시간", "입점 8개월", "정보공개서 최신 분기 반영", "카드매출 인증" 같은 배지는 데이터로 검증되는 사실에만 붙는다. 결제했다는 이유로 붙는 배지는 없다("인증 업체" 같은 것도 결제 배지면 안 된다). 기업회원 '한마디' 승인 슬롯(3개)과 후기 노출은 결제 등급과 무관하다.
4. **유료 전환 유도는 "보이는 수요" 앞에서만.** 무료 한도가 찼을 때 카드는 계속 보이되 [답하기] 대신 [입점 업그레이드]가 뜨는 방식(지시문 E). 기능을 숨기거나, 무료 사용자의 화면을 일부러 나쁘게 만들거나, 취소 버튼을 숨기는 식의 다크패턴은 만들지 않는다. 해지는 가입과 같은 깊이의 화면에서 한 번에 된다.
5. **AI 호출을 유료의 근거로 쓰지 않는다.** "AI 소개글은 프리미엄" 같은 구분은 하지 않는다. 화면에 "AI"라는 말 자체가 없다. 프리미엄이 파는 건 정보·시간·응답 권한이지 기술이 아니다.

## 2. 기업회원 입점 — 고려사항

이 층이 주 수익원이다(개인 양도인이 아니라 B2B 업체에서 번다). 설계할 때 아래를 지킨다.

**(a) "바로 유료 입점" 경로를 기본 문으로 둔다.** 진지한 업체는 첫날부터 돈을 낸다. 기업회원 가입 흐름은 "무료로 시작 → 나중에 업그레이드"가 아니라, 유료 입점이 첫 화면에 오고 무료 입점은 "먼저 둘러볼게요" 링크로 둔다. 무료 입점을 없애지는 않는다(입점 수 자체가 초기엔 공급이다).

**(b) 파는 것은 응답 권한과 도구다.** 유료 입점이 사는 것: 수요 신호 응답 무제한(무료는 월 N건, placeholder), 자동 첫 답장, 문의함 통계(지역×주제×시기 집계), 포트폴리오 슬롯 확장, 프로필 노출 자리의 수(노출 순서가 아니라 "내 상권 안에서 노출되는 화면의 종류"). 사지 못하는 것: 순서, 배지, 사용자 연락처, 신호를 보낸 사용자의 신원.

**(c) 핵심 지표는 회원 수가 아니라 "기업회원 1곳당 문의 수"다.** 입점 수보다 입점당 월 문의 수, 문의당 응답률, 응답→DM 전환율을 대시보드 첫 줄에 둔다. 이 숫자는 기업회원 본인 화면 첫 줄에도 보여준다("이번 달 받은 문의 12건 · 답한 문의 9건"). 문의가 0건인 유료 업체는 해지 위험이므로 운영 알림 대상이다.

**(d) 리드 단건 과금은 하지 않는다.** 리드 1건당 돈을 받으면 업체는 리드 품질에 화를 내고, 플랫폼은 리드 수를 늘리려 품질을 떨어뜨린다. 월 구독(입점료) 하나로 간다. 응답 건수 한도는 구독 등급 차이이지 건당 과금이 아니다.

**(e) 셀프서브가 기본이다.** 가입·결제·해지·등급 변경이 전부 앱 안에서 사람 개입 없이 된다. 영업 인력은 "대기 중 수요 신호가 있는데 입점 업체가 없는 지역"에만 쓴다(지시문 E의 pending 목록이 영업 리스트).

**(f) 기업회원은 문의를 받는 사용자이자 미래 경쟁자다.** 장기 방향(직접 중개·컨설팅 법인)과 충돌하지 않게, 노출 자리는 희소하게 유지하고, 문의 원장(연락처·문의 이력)은 플랫폼 자산으로 남긴다. 기업회원에게 원장 원본을 내보내는 기능은 만들지 않는다(집계만). 앱 내 문의는 기본값이지 강제가 아니다 — [문의하기]와 [전화하기]를 둘 다 두고 전화 클릭도 원장에 `channel=phone`으로 기록한다.

## 3. 프리미엄(개인) — 고려사항

**(a) 프리미엄이 파는 것은 "내 것에 대한 더 많은 정보와 더 빠른 처리"다.** 후보: 관심 흐름·문의 통계의 상세(비교군 확장, 주간 리포트), 사진 슬롯 확장, 매물 최신 확인·재게시 편의, 매출 월간 리포트 상세, 시세 알림 조건 수 확장. 무료에서 막지 않는 것: 등록·탐색·DM·기본 통계·매출 입력·카드매출 연동. 무료 사용자가 매물을 못 올리거나 문의를 못 받는 일은 없다.

**(b) 프리미엄은 "보상"으로도 준다.** `premium_grants`(팔렸어요 설문 → 30일, 카드매출 연동 → 30일)가 있다. 데이터를 주는 행동에 프리미엄 기간을 보상으로 주는 구조를 유지·확장한다. 보상으로 받은 기간과 결제한 기간은 같은 필드에서 관리하되 `reason`으로 구분해 "보상 프리미엄이 결제로 이어지는 비율"을 셀 수 있게 한다.

**(c) 시즌 함정을 피한다.** 프리미엄은 "등록 시점 1회 결제"가 아니라 월 구독이고, 사장님 축(매출 관리)의 상시 사용이 구독 유지의 근거가 되게 설계한다. 양도인 프리미엄 단독보다 "양도인+사장님" 겸업 사용자의 구독 유지율을 따로 본다.

**(d) 광고 단일 수익 구조로 가지 않는다.** 노출 광고 상품은 만들지 않는다(§1과 같은 얘기).

**(e) 40~60대 결제 UX.** 결제 화면은 한 화면, 월 금액 하나, 첫 달 안내 한 줄. 연 결제는 두되 기본 선택은 월 결제. 무료 체험이 있다면 종료 3일 전에 알림을 보내고 자동 전환 사실을 숨기지 않는다. 선불·충전 방식은 개인에게 쓰지 않는다.

## 4. 구현 규칙 (Claude Code)

- 모든 요금제 상수(등급 이름, 월 응답 한도, 사진 슬롯 수, 프리미엄 보상 일수, 금액)는 `config/plans.ts` 한 곳. 코드 다른 곳에 숫자 직접 쓰지 않는다. 미확정 값은 `// PLACEHOLDER — 대표 확정 전` 주석.
- `plan_tier` enum: 개인 `free | premium`, 기업회원 `vendor_free | vendor_paid`. 개인과 기업회원의 등급을 한 필드에 섞지 않는다(한 사람이 둘 다일 수 있다).
- 한도(quota)는 "이번 달 사용/한도" 두 필드 + 월초 리셋 배치. 한도 초과 시 기능을 숨기지 않고 [업그레이드] 버튼으로 바꾼다(§1-4).
- 결제·해지·등급 변경은 이벤트로 남긴다: `plan_view(tier)`, `plan_checkout_start(tier)`, `plan_paid(tier, amount)`, `plan_cancel(tier, reason_chip)`, `quota_blocked(feature)`, `upgrade_from_block(feature)`, `premium_granted(reason)`. 해지 사유는 칩 4개(placeholder)로 받되 건너뛰기 가능.
- 정렬·노출 코드에서 `plan_tier`·결제 여부·찜 수·후기 수(`review_count`)·`visibility`·`modu_vendor_id`를 참조하는 PR은 자동으로 막는 검사(`scripts/lint-pricing.mjs`, `npm run lint`)를 둔다. §1-1 위반은 버그다.
- 요금제 화면 문안은 "모두"가 화자, "AI" 단어 금지, "가게" 금지(사장님 축 제외). 정직 원칙: 실제 데이터로 뒷받침되지 않는 효능 문구("문의가 3배 늘어요")는 쓰지 않는다.
- 이 문서와 어긋나는 요청(예: "유료 업체를 위로 올려줘")을 받으면 구현하지 말고 멈춰서 대표에게 확인한다.

## 5. 대표가 확정할 것 (확정되면 이 문서와 `config/plans.ts`를 같이 갱신)

- 기업회원 등급 수(2단계로 시작할지, 지역 규모별 3단계로 갈지)와 월 입점료.
- 무료 입점의 월 응답 건수(지시문 E placeholder 3건)와 유료의 한도(무제한 제안).
- 개인 프리미엄 월 금액과 포함 항목의 최종 목록.
- 보상 프리미엄의 최대 누적 기간(예: 90일 상한).
- 무료 체험 유무와 기간.
