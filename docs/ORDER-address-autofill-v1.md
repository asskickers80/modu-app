# [ORDER-address-autofill-v1] 주소+호실 → 공공데이터 자동 채움 (양도인·소유주 등록)

■ 저장 지시: docs/ORDER-address-autofill-v1.md 저장.
■ 모드: 자율 판정. 멈춤 (a)스키마 SQL (b)실DB 정정 (c)판정 불가만.
■ 장치 3(양도인 diff 요약) 의무 — E1 1단계 직접 수정.
■ 범위: 공공데이터 자동 채움만. 사진 초안·플레이스 캡처는 후속. 현행 등록 순서 유지
   (주소 먼저) — 주소 선택 직후 자동 채움 확인 단계를 끼움.

■ 배경
지금은 주소 선택 후 층·면적을 직접 입력. 건축물대장·업종 조회로 절반을 자동 채우면
입력 부담이 줄고, 확보되는 층·면적·연식은 문의 동향 카드·시세 비교 재료로 재사용됨.
기존 (예정) 표기된 "건축물대장 자동조회"를 실구현하는 것.

■ 1. 선행 — 키
- 국토부 건축물대장 API: 공공데이터포털 활용신청 필요 (대표 실행 — 신청 절차 안내할 것.
  자동승인, 1~2시간). 기존 PUBLIC_DATA_KEY와 동일 포털이라 같은 키로 될 가능성 확인.
- 소진공 상가정보 API: 기존 키 재사용.
- 키 도착 전: 자동 채움 없이 현행(직접 입력) 동작 유지. 키 오면 활성.

■ 2. 자동 채움 대상 (주소 선택 직후 실행, 서버 프록시 경유)
[자동] 좌표·행정동·법정동코드 (기존 지오코딩) / 층·전용면적·주용도·사용승인일
(건축물대장 전유부 — 집합건물 아니면 표제부 층별 개요로 폴백) / 반경 200m 동일 업종 수
(소진공, 소개글 재료로 이미 쓰는 것과 공유).
[확인 칩] 현재 업종 — 소진공 해당 주소 업소의 표준산업분류 → "이 업종 맞아요?"
[맞아요 / 다른 업종이에요]. 소진공 데이터는 폐업·이전 반영이 늦으므로 확인 필수(정직).
양도인만 — 소유주 상가는 업종 확인 대신 이전 업종 힌트로만(시설 현황 단계의 이전 업종
칩 기본값 제안).
[직접 입력 유지] 권리금·보증금·월세·관리비·월매출·양도 사유·잔여 계약기간 — 무변경.

■ 3. 확인 UI
자동 채움 결과를 확인 카드로 표시 — "건축물대장에서 가져왔어요: 1층 · 45.2㎡ · 2009년
준공" + [맞아요] [고칠게요]. 고칠게요 → 기존 직접 입력 필드로(자동값이 초기값).
조회 실패·미매칭 시 현행 직접 입력으로 조용히 폴백 (에러 노출·가짜값 금지).
자동 채움 값과 사용자 수정 값 구분 저장(출처 필드 또는 플래그 — 판정 자율).

■ 4. 주소 파싱 (가장 손 많이 가는 부분 — 판정 근거 보고)
Daum 콜백의 시군구코드·번지·건물명 → 건축물대장 조회 파라미터. 집합건물 여부 판단,
호실 표기 불일치("101호" vs "1층 1호") 처리 방식 제안. 매칭 실패율 예상과 폴백 정책.
기존 우편번호·건물명 승격 유보분(address-real 때)이 여기서 필요해지면 컬럼 추가 SQL(a).

■ 5. 저장
사용승인일(건물 연식)·주용도 저장 컬럼 필요 시 SQL(a). 면적·층은 기존 컬럼.
법정동코드는 향후 인근 실거래 조회 키 — 저장 필수.
소개글 프롬프트에 연식·용도 주입 (집필 원칙 상수 확장).

■ 테스트: 자동 채움 성공 → 확인 카드 → 맞아요 → 저장 / 고칠게요 → 수정값 저장 /
   조회 실패 → 직접 입력 폴백 / 업종 확인 칩 분기 / 키 부재 시 현행 동작. 전체 스위트.

   매칭 실패 폴백 정책 + 양도인 diff 요약.
