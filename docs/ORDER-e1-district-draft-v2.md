# [ORDER-e1-district-draft-v2] E1 소개글 상권 실값 + 그라운딩 — 양도인 보호장치 포함

■ 모드: 자율 판정. 멈춤 (a)(b)(c)만.

## 0. 양도인 보호장치 (이번 오더부터 상시 원칙)

### 장치 1 — 스냅샷 선행
E1 관련 수정 착수 전, 양도인 핵심 플로우의 현재 정상 동작을 스냅샷 테스트로 고정:
등록 단계 완주 → 소개글 생성·편집·확정 → 공개 → E2 표시 → 수정 진입(값 로드·사진 보존)
→ 저장(공개 유지). 이미 있는 테스트는 재사용, 빈 구간만 신설. 이 스위트가 그린인 상태를
커밋으로 남긴 뒤 본작업 시작 — "건드리기 전 정상"의 증거를 먼저 확보.

### 장치 2 — 변경 격리
E1 공유 코드 수정 시 diff 원칙: 양도인 경로의 동작 변경은 이 오더가 명시한 4건
(프롬프트 주입·그라운딩·순차화·로딩)만 허용. 그 외 양도인 코드는 리팩토링 포함 일체 불변.
공용 함수 시그니처 변경 시 기존 호출부 동작 보존을 diff로 증명.

### 장치 3 — 보고 의무
보고에 "양도인 영향 diff 요약" 섹션 신설: 이번 커밋이 양도인 경로에서 바꾼 것 / 안 바꾼 것을
명시. 스냅샷 스위트 전후 그린 확인 첨부. 이후 E1을 건드리는 모든 오더에 이 섹션 의무화
(CLAUDE.md에 규칙 추가).

## 본작업 (4건 한정)
1. generateListingDraft(data, district): 상권 실값 섹션 주입 + "확정 사실로 인용 가능" 지시
   (임대인 패턴 동일).
2. 그라운딩: 최초 생성·전체 재생성만, 블록 수정 요청 제외, 거부 시 그라운딩 없이 1회 재시도,
   날조 금지 강제 동일.
3. E1Step2 generate() 순차화: 상권 → 초안 (E1p 방식).
4. 로딩: 단계형 통일하되 실호출 항목만 ("위치·상권 데이터 수집 중" + "소개글 쓰는 중").
   실호출 없는 항목 연출 금지.

## 테스트
장치 1 스냅샷 스위트 전후 그린 + 프롬프트 실값 주입 단언 + 생성문 상권 수치 실증. 전체 스위트.
